# DVE PPP — โจทย์ออกแบบระบบใหม่ (Redesign Brief)

เอกสารนี้สรุประบบ **DVE PPP Management System** ของเดิมทั้งหมด เพื่อส่งต่อให้ Claude Design
ออกแบบ UI ระบบใหม่ในรูปแบบ **Admin Bootstrap** โทนสีหลัก **แดงเลือดหมู** รองรับ **โหมดสว่าง/มืด**
โดยระบบใหม่ต้องทำงานกับ **ฐานข้อมูลเดิม (schema เดิม ห้ามแก้โครงสร้าง)**

> **บริบทสำคัญ:** ระบบเดิมพัฒนาโดยโปรแกรมเมอร์หลายคนต่อ ๆ กัน และความต้องการของผู้ใช้เปลี่ยนบ่อย
> ทำให้โครงสร้างกระจัดกระจาย มีหน้าจอซ้ำซ้อน เมนูไม่สอดคล้องกัน และมีโค้ดค้างที่ไม่ได้ใช้
> เป้าหมายของงานนี้คือ **จัดระเบียบประสบการณ์ผู้ใช้ใหม่ทั้งหมด** ไม่ใช่การทำหน้าเดิมให้สวยขึ้นเฉย ๆ

## 1. ระบบนี้คืออะไร

**PPP = Public Private Partnership** — ระบบติดตามความร่วมมือระหว่างอาชีวศึกษากับสถานประกอบการ
ในนิคมอุตสาหกรรมทั่วประเทศ ภายใต้สำนักงานคณะกรรมการการอาชีวศึกษา (สอศ.)

กระบวนการจริงในแต่ละปีการศึกษา:

1. **ส่วนกลาง (Admin)** มอบหมายให้ "สำนักงานอาชีวศึกษาจังหวัด (สอจ.)" แต่ละแห่ง รับผิดชอบนิคมอุตสาหกรรม
   และกำหนด **โควตาเป้าหมาย** ว่าต้องออกสำรวจสถานประกอบการกี่แห่ง
2. **สอจ.** ลงพื้นที่เข้าพบสถานประกอบการ แล้วบันทึกแบบสำรวจ (แบบฟอร์มราชการ **PPP-002**) เข้าระบบ
   ว่าสถานประกอบการต้องการ **นักเรียน/นักศึกษาสาขาใด ระดับใด จำนวนเท่าไร** สำหรับ
   **ฝึกงาน (Internship)** และ **ทวิภาคี (DVE)**
3. **สอจ.** อัปโหลดเอกสารหลักฐานการดำเนินงานตามขั้นตอน (หนังสือนำ, คำสั่งฯ, แผนงาน ฯลฯ)
4. **ส่วนกลาง** ติดตามความคืบหน้ารายนิคม/ราย สอจ. และออกรายงานสรุป
5. **สาธารณะ** ดูสถิติภาพรวมและค้นหาข้อมูลสถานประกอบการได้

### ขนาดข้อมูลจริงบน Production (ใช้ออกแบบตาราง/หน้ารายการ)

| รายการ | จำนวน |
|---|---|
| นิคมอุตสาหกรรม | **75** แห่ง |
| สอจ. (ผู้ใช้งานหลัก) | **~80** แห่ง |
| สถานประกอบการทั้งหมด (เป้าหมาย) | **4,817** แห่ง |
| สถานประกอบการที่บันทึกเข้าระบบแล้ว | **2,721** แห่ง (56.49%) |
| ที่แจ้ง "ไม่ประสงค์รับนักเรียน/นักศึกษา" | **1,742** แห่ง |
| แบบสำรวจ (surveys) | ~2,722 ชุด |
| รายการความต้องการกำลังคน | ~2,020 แถว |
| ข้อสรุปการประชุม | ~3,047 แถว |
| สาขาวิชาในหลักสูตร | 171 สาขา (ปวช. 67 / ปวส. 105) |
| สถานศึกษา | 433 แห่ง |
| ไฟล์เอกสารที่อัปโหลด | ~460 ไฟล์ |

**ข้อสังเกตด้านการออกแบบ:** ตารางหลักมีระดับพัน ๆ แถว จึงต้องออกแบบให้มี
ค้นหา + กรอง + เรียงลำดับ + แบ่งหน้า เป็นมาตรฐานทุกหน้ารายการ และรองรับการ export

## 2. ผู้ใช้และบทบาท

ระบบเดิมมี "ระบบล็อกอิน" แยกกัน 2 ชุดโดยสิ้นเชิง ไม่มีตารางผู้ใช้กลาง ไม่มีคอลัมน์ role
**ระบบใหม่ควรรวมเป็นระบบสิทธิ์เดียวที่มี role ชัดเจน** (โดยยังอ่านผู้ใช้จากตารางเดิมได้)

| บทบาท | ล็อกอินด้วย | ขอบเขตข้อมูล | งานหลัก |
|---|---|---|---|
| **ผู้ดูแลระบบ (Admin)** | ตาราง `admins` (username + bcrypt) | ทั้งประเทศ | มอบหมายนิคมฯ, กำหนดโควตา, ติดตามภาพรวม, สวมสิทธิ์ (impersonate) |
| **สอจ. (PVEO)** | ตาราง `provincial_vocational_offices` (รหัสวิทยาลัย) | เฉพาะนิคมฯ ที่ได้รับมอบหมาย | บันทึกแบบสำรวจ, จัดการสถานประกอบการ, อัปโหลดเอกสาร, ดูรายงานของตน |
| **ผู้เข้าชมทั่วไป** | ไม่ต้องล็อกอิน | อ่านอย่างเดียว | ดูสถิติภาพรวม, ค้นหาสถานประกอบการ, ดาวน์โหลดแบบฟอร์ม |
| **ผู้รับลิงก์แชร์** | ไม่ต้องล็อกอิน (token ใน URL) | อ่านอย่างเดียว เฉพาะหน้ารายงานที่แชร์ | ดูหน้าติดตามผลที่ผู้ดูแลส่งลิงก์ให้ |

### ปัญหาสิทธิ์ที่ต้องแก้ในระบบใหม่ (สำคัญมาก)

- รหัสผ่านของ สอจ. เก็บเป็น **plaintext** และในข้อมูลจริง **รหัสผ่าน = ชื่อผู้ใช้ = รหัสวิทยาลัย**
  (เช่น user `1310106101` / pass `1310106101`) — ระบบใหม่ต้องออกแบบหน้าจอรองรับ
  **การตั้งรหัสผ่านใหม่ครั้งแรก** และ **การเปลี่ยนรหัสผ่าน**
- การล็อกอินฝั่ง สอจ. ใช้ SQL แบบต่อสตริง (เสี่ยง SQL injection)
- Admin หมดเวลาอัตโนมัติ 30 นาที ส่วน สอจ. ไม่มี timeout เลย → ควรทำให้เหมือนกัน

### แนวคิด "นิคมฯ ที่กำลังทำงานอยู่" (Active Estate) — ต้องคงไว้

สอจ. หนึ่งแห่งอาจดูแลหลายนิคมฯ ระบบเดิมบังคับให้ **เลือกทำงานทีละนิคมฯ** โดยเก็บไว้ใน session
และเกือบทุกหน้าจะกรองข้อมูลตามนิคมฯ ที่เลือกอยู่

ระบบใหม่ควรทำให้ชัดเจนกว่าเดิมด้วย **ตัวสลับนิคมฯ (estate switcher) ที่มองเห็นตลอดเวลาบน top bar**
พร้อมแสดงชื่อนิคมฯ ที่กำลังทำงานอยู่ ไม่ใช่ซ่อนอยู่ในเมนูย่อยเหมือนเดิม

## 3. ปัญหาของระบบเดิมที่ต้องแก้ด้วยการออกแบบใหม่

จากการวิเคราะห์โค้ดทั้งระบบ (243 ไฟล์ PHP) พบปัญหาเชิงประสบการณ์ผู้ใช้ดังนี้:

**A. โครงสร้างเมนูไม่สอดคล้องกัน**
แต่ละกลุ่มหน้ามี navbar ของตัวเอง (5 ชุด) หน้าตาและตำแหน่งเมนูต่างกัน
ผู้ใช้ที่ข้ามไปมาระหว่างหน้าสาธารณะ / หน้า สอจ. / หน้า Admin จะรู้สึกเหมือนคนละระบบ

**B. หน้าจอซ้ำซ้อน**
มีหน้ารายการสถานประกอบการอย่างน้อย 3 เวอร์ชัน (สาธารณะ / สอจ. / Admin) ที่แสดงข้อมูลชุดเดียวกัน
คนละหน้าตา และหน้า dashboard ซ้ำกัน 2 ชุด

**C. แบบฟอร์มยาวมากในหน้าเดียว**
แบบสำรวจ PPP-002 มี **9 ส่วน** อยู่ในหน้าเดียวยาวกว่า 1,200 บรรทัด ผู้ใช้ต้องเลื่อนยาวมาก
ไม่มีตัวบอกความคืบหน้า ไม่มีการบันทึกร่าง กรอกผิดต้องเริ่มใหม่

**D. ฟีเจอร์ค้างครึ่งทาง**
ระบบอัปโหลดเอกสารออกแบบไว้ 5 ขั้นตอน แต่ปัจจุบันเปิดใช้จริงเพียง 2 ขั้นตอน
ส่วนที่เหลือยังค้างอยู่ในโค้ดและ API — ระบบใหม่ควรออกแบบให้ **จำนวนขั้นตอนกำหนดค่าได้**

**E. ปีการศึกษาเป็นค่าคงที่ในโค้ด**
`academic_year = '2568'` ถูก hardcode หลายจุด ต้องแก้โค้ดทุกปี
ระบบใหม่ต้องมี **ตัวเลือกปีการศึกษา** ในหน้าจอ และหน้าตั้งค่าสำหรับกำหนดปีที่ใช้งาน

**F. ไม่มีการยืนยันตัวเลขที่ผิดปกติ**
หน้าติดตามผลจริงแสดง "230.92%" เพราะจำนวนที่สำรวจมากกว่าเป้าหมาย
ระบบใหม่ต้องออกแบบการแสดงผลกรณีข้อมูลเกิน/ผิดปกติให้ชัดเจน (เช่น badge เตือน)

**G. ไม่มีโหมดมืด ไม่มีการออกแบบสำหรับมือถือจริงจัง**
ตารางกว้างมากล้นจอมือถือ ผู้ใช้ที่ลงพื้นที่จริงต้องใช้มือถือ/แท็บเล็ตกรอกข้อมูล

## 4. โครงสร้างระบบใหม่ที่เสนอ (Information Architecture)

```
┌─ สาธารณะ (ไม่ต้องล็อกอิน)

│   ├── ค้นหาสถานประกอบการ
│   ├── รายงานสาธารณะ (ผู้พิการ / สวัสดิการ / ความต้องการกำลังคน)
│   ├── ดาวน์โหลดแบบฟอร์มและคู่มือ
│   └── ผู้ช่วยตอบคำถาม (Chatbot)

├─ สอจ. (ล็อกอิน)
│   ├── แดชบอร์ดของฉัน — ความคืบหน้าเทียบโควตา
│   ├── สถานประกอบการ — รายการ / เพิ่ม / แก้ไข / ดูรายละเอียด
│   ├── แบบสำรวจ PPP-002 — สร้าง / แก้ไข (แบบหลายขั้นตอน)
│   ├── รายงานความคืบหน้า — อัปโหลดเอกสารตามขั้นตอน
│   ├── ข้อมูลนิคมฯ ที่รับผิดชอบ
│   ├── รายงานของฉัน
│   └── กระดานสนทนา
│
└─ ผู้ดูแลระบบ (ล็อกอิน)
    ├── แดชบอร์ดภาพรวมประเทศ
    ├── ติดตามข้อมูลนิคมอุตสาหกรรม  ★ มีปุ่มแชร์ลิงก์สาธารณะ
    ├── ตรวจสอบสถานะการอัปโหลดไฟล์  ★ มีปุ่มแชร์ลิงก์สาธารณะ
    ├── จัดการ สอจ. — บัญชีผู้ใช้ / มอบหมายนิคมฯ / โควตา
    ├── จัดการนิคมอุตสาหกรรม — ข้อมูลหลัก + รายละเอียด
    ├── รายงานและการส่งออก
    └── ตั้งค่าระบบ — ปีการศึกษา, ขั้นตอนเอกสาร, กำหนดส่ง
```

## 5. หน้าจอที่ต้องออกแบบ

เรียงตามลำดับความสำคัญ — **ลำดับ 1–6 คือหน้าที่ใช้งานหนักที่สุด ต้องออกแบบให้ครบก่อน**

### 5.1 ★ แดชบอร์ดผู้ดูแลระบบ (ภาพรวมประเทศ)

**ผู้ใช้:** Admin · **จุดประสงค์:** เห็นสถานะทั้งประเทศใน 5 วินาที

- **แถว KPI 5 ใบ:** จำนวนนิคมฯ (75) · สถานประกอบการทั้งหมด (4,817) · บันทึกแล้ว (2,721) ·
  ไม่ประสงค์รับนักเรียน (1,742) · ร้อยละความคืบหน้า (56.49%)
  แต่ละใบมีไอคอน ตัวเลขใหญ่ คำอธิบายใต้ตัวเลข และ sparkline เทียบปีก่อน
- **กราฟ:** ความคืบหน้ารายภาค (แท่งแนวนอน) · สัดส่วนความต้องการ ฝึกงาน vs ทวิภาคี (โดนัท) ·
  ความต้องการกำลังคน 10 สาขายอดนิยม (แท่ง)
- **ตารางสรุป:** สอจ. ที่คืบหน้าน้อยที่สุด 10 อันดับ พร้อมปุ่มลัดไปดูรายละเอียด
- **ตัวกรองด้านบน:** ปีการศึกษา · ภาค · จังหวัด

### 5.2 ★ ติดตามข้อมูลนิคมอุตสาหกรรม

**ผู้ใช้:** Admin + ผู้รับลิงก์แชร์ · **หน้านี้มีอยู่จริงและใช้งานหนัก**

- KPI 5 ใบ (เหมือนหัวข้อ 5.1) โดยการ**คลิก KPI = กรองตาราง**ด้านล่าง
- ตาราง 75 แถว: ชื่อนิคมฯ + จังหวัด · สอจ. ที่รับผิดชอบ (แสดงเป็น chip หลายอัน) ·
  จำนวนสถานประกอบการที่มี · จำนวนในระบบ · **ร้อยละพร้อมแถบความคืบหน้า** · จำนวนที่ไม่ประสงค์รับนักศึกษา
- ต้องออกแบบกรณี **ร้อยละเกิน 100%** (ข้อมูลจริงมี 230.92%) ให้เห็นว่าผิดปกติ
- ปุ่ม: แชร์ลิงก์ · รีเฟรช · ส่งออก Excel · พิมพ์

### 5.3 ★ ตรวจสอบสถานะการอัปโหลดไฟล์

**ผู้ใช้:** Admin + ผู้รับลิงก์แชร์

- KPI 4 ใบ: สอจ. ทั้งหมด (80) · อัปโหลดครบ (72) · อัปโหลดบางส่วน (4) · ยังไม่อัปโหลด (4)
- แถบตัวกรองแบบปุ่ม: ทั้งหมด / ครบแล้ว / บางส่วน / ยังไม่อัปโหลด + ช่องค้นหา + ปุ่มดาวน์โหลด ZIP
- ตาราง 80 แถว: สอจ./วิทยาลัย (+ รหัส) · จังหวัด · นิคมฯ ที่รับผิดชอบ ·
  **คอลัมน์ต่อขั้นตอน** แสดง badge ของเอกสารแต่ละชนิด (ครบ/ขาด) และสถานะ "Submit แล้ว" ·
  แถบความคืบหน้า % · สถานะรวม
- คลิกช่องขั้นตอน → เปิด modal รายการไฟล์ (พร้อมดูตัวอย่าง/ดาวน์โหลด)
- **โหมดลิงก์แชร์:** ซ่อนปุ่มดาวน์โหลดและปิดการเปิดไฟล์ แต่ยังดูสถานะได้ครบ

### 5.4 ★★ แบบสำรวจ PPP-002 (หน้าสำคัญที่สุด — ต้องออกแบบใหม่ทั้งหมด)

**ผู้ใช้:** สอจ. · เดิมเป็นฟอร์มยาว 9 ส่วนในหน้าเดียว
**เสนอให้ออกแบบเป็น multi-step wizard พร้อมแถบความคืบหน้าและบันทึกร่างอัตโนมัติ**

โครงสร้างข้อมูลที่ต้องกรอก (ห้ามตัดออก — เป็นแบบฟอร์มราชการ):

| ขั้น | หัวข้อ | ข้อมูล |
|---|---|---|
| 0 | ข้อมูลสถานประกอบการ | ชื่อ, เลขผู้เสียภาษี, ลักษณะกิจการ, ที่อยู่ (จังหวัด→อำเภอ→ตำบล→ไปรษณีย์ แบบ cascade), นิคมฯ, โทร, อีเมล |
| 0 | ผู้ประสานงาน | ชื่อ, ตำแหน่ง, โทร, Line ID |
| 1 | ข้อมูลการลงพื้นที่ | วันที่ลงพื้นที่, สถานศึกษาที่ลงพื้นที่, จังหวัดพื้นที่ดำเนินการ |
| 2 | ประวัติการรับนักศึกษา | สาขา + จำนวนที่เคยรับ |
| 3 | **ความต้องการกำลังคน** | เช็กบ็อกซ์ "ไม่ประสงค์รับนักเรียน/นักศึกษา" · ปีการศึกษา (พ.ศ.) · รอบการสำรวจ · **ตารางแถวแบบเพิ่มได้ 4 กลุ่ม: ฝึกงาน-ปวช. / ฝึกงาน-ปวส. / ทวิภาคี-ปวช. / ทวิภาคี-ปวส.** แต่ละแถว = สาขาวิชา (ค้นหาได้จาก 171 สาขา), จำนวนชาย/หญิง, รับผู้พิการ (+ประเภทความพิการ), ลักษณะงาน, ทักษะที่ต้องการ, ช่วงเวลา |
| 4 | รับครูฝึกประสบการณ์ | รับ/ไม่รับ + รายละเอียด |
| 5 | สวัสดิการ | ทุนการศึกษา (+จำนวนเงิน), เบี้ยเลี้ยง (+จำนวน), ประกันอุบัติเหตุ, ยูนิฟอร์ม, ที่พัก (+รายละเอียด), อื่น ๆ |
| 6 | ข้อสรุปการประชุม | รายการข้อความแบบเพิ่มได้หลายข้อ |
| 7 | ข้อเสนอแนะ | ข้อความยาว |
| 8 | ปัญหาและอุปสรรค | ข้อความยาว |
| 9 | ผู้รับรองข้อมูล | ชื่อ, ตำแหน่ง, โทรศัพท์ |

**สิ่งที่ต้องออกแบบเป็นพิเศษ:**
- แถบขั้นตอนด้านบน (stepper) ที่บอกว่าขั้นไหนกรอกครบแล้ว/ยังขาด
- แถวความต้องการกำลังคนที่ **เพิ่ม/ลบได้** และดูดีบนมือถือ (การ์ดแทนตารางเมื่อจอแคบ)
- เมื่อติ๊ก "ไม่ประสงค์รับนักเรียน" ต้องซ่อน/ปิดส่วนความต้องการทั้งหมดอย่างชัดเจน
- ตัวบ่งชี้ **คะแนนความสมบูรณ์ของข้อมูล (0–100)** แบบเรียลไทม์ขณะกรอก (ดูสูตรในข้อ 7.3)
- ปุ่มบันทึกร่าง + เตือนก่อนออกจากหน้าเมื่อยังไม่บันทึก

### 5.5 ★ รายการสถานประกอบการ (ของ สอจ.)

- หัวข้อหน้าแสดง **ชื่อนิคมฯ ที่กำลังทำงานอยู่** + ปุ่มดูข้อมูลนิคมฯ / แก้ไข (ถ้าเป็นเจ้าของ)
- แถบสรุป: เป้าหมาย vs บันทึกแล้ว + แถบความคืบหน้า
- ตาราง: ชื่อสถานประกอบการ · ลักษณะกิจการ · ผู้ประสานงาน · วันที่สำรวจล่าสุด ·
  **คะแนนความสมบูรณ์ (แถบสี)** · สถานะไม่รับนักศึกษา · ปุ่มดู/แก้ไข/ลบ
- ปุ่มหลัก: **+ บันทึกแบบสำรวจใหม่** (เด่นชัด มุมขวาบน)

### 5.6 ★ รายงานความคืบหน้า / อัปโหลดเอกสาร (ของ สอจ.)

- การ์ดรายขั้นตอน (ปัจจุบัน 2 ขั้น แต่ต้องรองรับได้ถึง 5) แต่ละการ์ดมี:
  ชื่อขั้นตอน · เอกสารที่ต้องมี · **วันครบกำหนด** (เช่น 25 พฤษภาคม 2569) ·
  พื้นที่ลากวางไฟล์ · รายการไฟล์ที่อัปโหลดแล้ว · ช่องหมายเหตุ · ปุ่มบันทึกร่าง / ปุ่มยืนยันเสร็จสิ้น
- ขั้นตอนถัดไป **ล็อก** จนกว่าขั้นก่อนหน้าจะเสร็จ — ต้องออกแบบสถานะ "ล็อก" ให้ชัด
- ไทม์ไลน์ประวัติการดำเนินการ (activity log)

## 6. ระบบออกแบบ (Design System)

### 6.1 โทนสีหลัก — แดงเลือดหมู

ใช้เป็น CSS custom properties ทั้งหมด เพื่อสลับโหมดสว่าง/มืดได้

```css
/* Brand scale — แดงเลือดหมู (Oxblood / Maroon) */
--brand-50:  #FBF0F2;
--brand-100: #F5DDE1;
--brand-200: #E6B3BC;
--brand-300: #CE7B89;
--brand-400: #B14A5C;
--brand-500: #94293D;
--brand-600: #7F2233;
--brand-700: #6D1A26;   /* ★ สีหลัก "เลือดหมู" — ใช้ในโหมดสว่าง */
--brand-800: #5E1520;
--brand-900: #4A0F18;
```

**โหมดสว่าง:** ปุ่มหลัก/หัวตาราง/แถบเมนู = `--brand-700` บนพื้นขาว
**โหมดมืด:** พื้นหลังโทนอุ่นเข้ม `#161113` / การ์ด `#1E1719` / ปุ่มหลักเลื่อนขึ้นเป็น `--brand-400`
เพื่อให้ค่าความต่างของสี (contrast) ผ่านเกณฑ์ WCAG AA

### 6.2 สีสถานะ — ต้องแยกจากสีแบรนด์ให้ชัด

เนื่องจากสีแบรนด์เป็นแดงเข้ม **ห้ามใช้แดงเข้มแทนสถานะผิดพลาด** เพราะจะสับสน

| สถานะ | โหมดสว่าง | โหมดมืด | ใช้กับ |
|---|---|---|---|
| สำเร็จ / ครบแล้ว | `#0F7B3D` | `#3DBE72` | อัปโหลดครบ, Submit แล้ว |
| เตือน / บางส่วน | `#B45309` | `#F0A44A` | อัปโหลดบางส่วน, ใกล้ครบกำหนด |
| ผิดพลาด / ยังไม่ทำ | `#D92D20` | `#FF6B5E` | ยังไม่อัปโหลด, เกินกำหนด |
| ข้อมูล | `#1B6DA8` | `#5AB0E6` | คำแนะนำ, สถานะกลาง |
| ปิดใช้งาน / ล็อก | `#6B7280` | `#9CA3AF` | ขั้นตอนที่ยังล็อก |

**ทุกสถานะต้องมีไอคอนกำกับเสมอ** ไม่พึ่งสีอย่างเดียว (เพื่อผู้ใช้ตาบอดสี)

### 6.3 ตัวอักษร

- ฟอนต์: **Sarabun** (ฟอนต์ราชการไทย) น้ำหนัก 300/400/500/600/700 — ใช้ทั้งระบบรวมถึงตัวเลข
- ขนาดฐาน 15–16px, ตารางใช้ 14px, ตัวเลข KPI 32–40px น้ำหนัก 700
- ข้อความไทยยาวต้องมี `line-height` อย่างน้อย 1.6

### 6.4 องค์ประกอบ (Components) ที่ต้องออกแบบให้ครบ

- **Sidebar** ยุบ/ขยายได้ + **Top bar** (ตัวสลับนิคมฯ, ตัวเลือกปีการศึกษา, สลับโหมดมืด/สว่าง, เมนูผู้ใช้)
- **การ์ด KPI** (ไอคอน + ตัวเลข + คำอธิบาย + แนวโน้ม + สถานะกรองอยู่)
- **ตารางข้อมูล** — หัวตารางค้างเมื่อเลื่อน, เรียงลำดับ, ค้นหา, แบ่งหน้า, เลือกหลายแถว, ส่งออก,
  และ**ต้องมีเวอร์ชันการ์ดสำหรับมือถือ**
- **แถบความคืบหน้า** ทั้งแบบเส้นและแบบวงกลม (พร้อมสถานะเกิน 100%)
- **Badge/Chip** สำหรับสถานะเอกสาร, สาขาวิชา, จังหวัด
- **Stepper** สำหรับฟอร์มหลายขั้นตอนและขั้นตอนเอกสาร (มีสถานะ: เสร็จ/กำลังทำ/ล็อก)
- **พื้นที่อัปโหลดไฟล์** แบบลากวาง + รายการไฟล์ + ดูตัวอย่าง PDF
- **Modal** ขนาด sm/lg/xl, **Toast**, **Empty state**, **Skeleton loading**
- **ตัวเลือกที่อยู่แบบลูกโซ่** จังหวัด → อำเภอ → ตำบล → รหัสไปรษณีย์อัตโนมัติ
- **ตัวเลือกสาขาวิชาแบบค้นหาได้** (171 ตัวเลือก จัดกลุ่มตามประเภทวิชา)
- **แบนเนอร์โหมดสวมสิทธิ์** (เมื่อ Admin เข้าใช้แทน สอจ.) และ **แบนเนอร์โหมดดูสาธารณะ**

### 6.5 หลักการอื่น

- Bootstrap 5 grid, มุมโค้ง 8–12px, เงาอ่อน, ระยะห่างมาตรฐาน 4/8/12/16/24/32px
- ทุกหน้าต้องออกแบบ 3 ขนาด: มือถือ 375px · แท็บเล็ต 768px · เดสก์ท็อป 1440px
- ต้องมีสไตล์สำหรับ **พิมพ์ (print)** เพราะผู้ใช้พิมพ์รายงานส่งราชการจริง
- ข้อความทั้งหมดเป็นภาษาไทย, ปีเป็น **พ.ศ.**, วันที่รูปแบบ `dd/mm/yyyy`

## 7. กฎธุรกิจที่ระบบใหม่ต้องรักษาไว้

### 7.1 ปีการศึกษาเป็น พ.ศ.
`surveys.survey_year` และ `pveo_estate_assignments.survey_year` เก็บเป็น พ.ศ. (`ค.ศ. + 543`)
รอบการสำรวจ (`survey_round`) มี 4 ค่า: `1` = ภาคเรียนที่ 1 · `2` = ภาคเรียนที่ 2 ·
`3` = ภาคฤดูร้อน · `Yearly` = ตลอดปีการศึกษา

### 7.2 การมอบหมายและโควตา
- `industrial_estate_responsibility` (is_active = 1) กำหนดว่า สอจ. ใดดูแลนิคมฯ ใด — **หนึ่งนิคมฯ อาจมีหลาย สอจ.**
- `pveo_estate_assignments` เก็บเป้าหมายรายปี (unique: pveo + estate + year)
- มี stored procedure `SyncPveoEstateAssignments(ปี)` ที่คำนวณยอดสำรวจจริงและ**ไม่เขียนทับโควตา
  ที่ตั้งไว้เองเมื่อมีหลาย สอจ. ดูแลนิคมเดียวกัน**

### 7.3 คะแนนความสมบูรณ์ของข้อมูล (0–100)
เก็บใน `enterprise_completeness` คำนวณจาก:

| องค์ประกอบ | คะแนน | เงื่อนไข |
|---|---|---|
| ข้อมูลพื้นฐาน | 10 | มีชื่อ + จังหวัด |
| ผู้ติดต่อ | 5 | มีชื่อ หรือ ตำแหน่งผู้ประสานงาน |
| ช่องทางติดต่อ | 5 | มีโทรศัพท์ หรือ Line ID |
| **ความต้องการกำลังคน** | **60** | มีรายการความต้องการอย่างน้อย 1 แถว |
| ข้อสรุปการประชุม | 10 | ข้อความยาว ≥ 20 ตัวอักษร |
| ข้อเสนอแนะ | 10 | ข้อความยาว ≥ 20 ตัวอักษร |

ข้อความว่าง, `-`, `ไม่มี`, `n/a` ถือว่าไม่มีข้อมูล
**ต้องออกแบบให้ผู้ใช้เห็นคะแนนนี้และรู้ว่าต้องกรอกอะไรเพิ่มเพื่อให้คะแนนเต็ม**

### 7.4 ขั้นตอนเอกสาร
`report_progress` (unique: pveo + estate + ปี + ขั้นตอน) สถานะ `draft` / `submitted` / `done`
ชนิดไฟล์: `letter` หนังสือนำ · `order` คำสั่งฯ · `plan` แผนงาน · `report1` · `report2` · `summary`
ไฟล์เก็บใน `report_files` (ลบแบบ soft delete) และมี activity log ทุกการกระทำ

### 7.5 การบันทึกแบบสำรวจ
เมื่อแก้ไขแบบสำรวจ ระบบเดิม **ลบแล้วเขียนใหม่ทั้งชุด** สำหรับความต้องการ/ความพิการ/ข้อสรุปการประชุม
ระบบใหม่ควรออกแบบให้ผู้ใช้เห็นชัดว่ากำลังแก้ไขข้อมูลชุดใด และมีการยืนยันก่อนบันทึกทับ

### กลุ่มตารางหลัก

```
enterprises (สถานประกอบการ)

industrial_estates (นิคมฯ)
   ├── industrial_estate_details (รายละเอียด 1:1)
   ├── industrial_estate_responsibility (มอบหมาย → สอจ.)

provincial_vocational_offices (สอจ.) ── college (สถานศึกษา)

report_progress (ขั้นตอน) ── report_files (ไฟล์) ── report_activity_log

ข้อมูลอ้างอิง: provinces / districts / sub_districts / geographies /

กระดานสนทนา: topics / replies
```

- `survey_demands`: `system_type` (`internship` | `dve`), `course_code`,
  `vc_male` `vc_female` (ปวช. ชาย/หญิง), `hvc_male` `hvc_female` (ปวส. ชาย/หญิง),
  `disability_flag`, `job_description`, `required_skills`
- `surveys`: `no_student_required` (ไม่ประสงค์รับนักศึกษา), สวัสดิการ 6 ประเภท,
  `teacher_training_status`, `suggestion_text`, `problem_obstacle`, ผู้รับรอง 3 ฟิลด์
- `industrial_estate_details`: พื้นที่รวม/ขาย/คงเหลือ (ไร่), จำนวนโรงงานแยก 4 กลุ่มอุตสาหกรรม
  (วิศวกรรม/ดิจิทัล/บริการ/ชีวภาพ), บริการ OSS/EEC/BOI/พัฒนาทักษะ, ผู้ประสานงาน

### ข้อควรระวังเรื่องข้อมูล

- `provincial_vocational_offices.college_password` เป็น **plaintext** และเท่ากับ `college_code`
- ตาราง `topics`/`replies` เก็บ `created_at` เป็น **varchar** ไม่ใช่ datetime และเก็บรูปเป็น base64
- ไฟล์ `schema.sql` ที่ export มา **มี trigger 3 ตัวที่ body ถูกตัดไม่สมบูรณ์**
  (`after_survey_insert`, `after_survey_delete`, `after_enterprise_completeness_update`)
  ต้อง export ใหม่จาก production ก่อนนำไปสร้างฐานข้อมูลใหม่
- นิคมฯ บางแห่งไม่มี `province_id` (แสดงเป็น "ไม่ระบุจังหวัด") — ต้องออกแบบรองรับค่าว่าง

## 9. สิ่งที่ต้องการจากการออกแบบ

**ให้ออกแบบเป็น artboards** เรียงตามลำดับนี้:

1. **Design system sheet** — จานสีทั้งสองโหมด, ตัวอักษร, ปุ่มทุกสถานะ, badge, ฟอร์ม, การ์ด KPI
2. แดชบอร์ดผู้ดูแลระบบ (สว่าง + มืด)
3. ติดตามข้อมูลนิคมอุตสาหกรรม (สว่าง + มืด)
4. ตรวจสอบสถานะการอัปโหลดไฟล์
5. แบบสำรวจ PPP-002 — อย่างน้อย 3 ขั้นตอน (ข้อมูลสถานประกอบการ / ความต้องการกำลังคน / สรุป)
6. รายการสถานประกอบการของ สอจ.
7. รายงานความคืบหน้า/อัปโหลดเอกสาร
8. หน้าแรกสาธารณะ + หน้าค้นหา
9. หน้าเข้าสู่ระบบ + เลือกนิคมฯ
10. **มุมมองมือถือ** ของหน้า 5 และ 6 (หน้าที่ใช้ลงพื้นที่จริง)

**ใช้ข้อมูลจริงในการออกแบบ** เพื่อให้เห็นปัญหาความยาวข้อความไทย เช่น
"นิคมอุตสาหกรรมเอเซีย (สุวรรณภูมิ)", "วิทยาลัยเทคนิคกาญจนบุรี",
"การฝึกประสบการณ์สมรรถนะวิชาชีพ (ฝึกงาน)", "ไม่ประสงค์รับนักเรียน/นักศึกษา"
